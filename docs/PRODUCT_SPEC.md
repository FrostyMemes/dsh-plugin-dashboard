# DSH Agent Control Center — спецификация продукта

- **Статус:** канонический источник продуктовых и бизнес-требований
- **Версия:** 1.0
- **Дата:** 2026-10-14
- **Продукт:** read-only плагин для официального DeepSeek Harness Desktop
- **Основной интерфейс:** отдельная страница в обычном браузере

## 1. Назначение документа и источник истины

Этот документ фиксирует, **какую пользовательскую ценность обязан обеспечивать плагин, какие бизнес-правила он соблюдает и что входит в MVP**. Он является источником истины для продуктового смысла. Реализация, названия API и технические предложения не могут незаметно менять эти правила.

Документы проекта имеют разные роли:

1. **`docs/PRODUCT_SPEC.md` — продуктовая истина.** Цель, границы, значения терминов, правила представления данных, приватность и критерии пользовательской приёмки.
2. **`DSH_AGENT_CONTROL_CENTER_CODEX_SPEC.md` — подробный проектный и технический дизайн.** Он помогает реализовать продукт, но не подтверждает, что Harness предоставляет описанные в нём API. Если его трактовка расходится с этим документом, приоритет у продуктовой истины; расхождение нужно разрешить до реализации.
3. **`docs/COMPATIBILITY.md` — технические свидетельства.** Фиксирует конкретные версии Desktop, найденные API и результаты проверок. Каждый факт относится только к указанной версии и уровню проверки.
4. **`README.md` — краткая инструкция по разработке и текущее состояние.** Он не заменяет спецификацию.
5. **Исходный код — реализация требований.** Если он расходится с утверждёнными требованиями, это дефект либо повод предложить явное изменение этой спецификации.

Изменение бизнес-правил, целевой аудитории, приватности, read-only границы или MVP требует явного продуктового решения. Техническая возможность сама по себе не является разрешением расширить продукт.

## 2. Продукт и пользователь

### 2.1. Проблема

Оператор DeepSeek Harness Desktop должен переключаться между сессиями, чтобы понять, какие агенты сейчас существуют, в каком подтверждённом состоянии они находятся и какие безопасно доступные метрики сообщены Harness.

### 2.2. Обещание продукта

Agent Control Center показывает в браузере **доступное текущее состояние одного работающего экземпляра официального DeepSeek Harness Desktop** и обновляет его без ручного перезапуска страницы. Панель наблюдает; решения о запуске и ходе задач остаются в Desktop.

Панель обязана показывать границы наблюдения: неизвестные, отсутствующие и неполные сведения должны оставаться неизвестными, отсутствующими или неполными в интерфейсе.

### 2.3. Пользовательский сценарий

1. Пользователь запускает официальный Desktop с одним Host.
2. Из установленного Bundle он открывает браузерную панель и связывает её с этим экземпляром.
3. В панели он просматривает сводку, карточки, дерево и подробности доступных агентов.
4. Изменения состояния приходят автоматически, пока соединение доступно.
5. Если соединение теряется или источник данных неполон, интерфейс сообщает об этом и не выдаёт неполную картину за полную.

## 3. Неизменяемые бизнес-правила

### 3.1. Один экземпляр и одна цель наблюдения

- Панель относится к одному работающему экземпляру официального Desktop/Host.
- Она не объединяет несколько Hosts, пользователей, компьютеров или Harness-процессов.
- Она показывает только данные, которые этот экземпляр действительно предоставляет плагину.
- Новые Harness, Agent или Session ради отображения панелью не запускаются.

### 3.2. Только наблюдение

- Плагин не отправляет команды агентам, не меняет их настройки, не запускает, не останавливает и не возобновляет задачи.
- Плагин не меняет ход выполнения задачи и не управляет сессиями.
- Любое управление работой остаётся в официальном Desktop.

### 3.3. Правдивость данных

- Живой агент и запись о дочерней сессии в каталоге — разные сущности.
- Известная дочерняя сессия сама по себе не доказывает, что она загружена или работает.
- Отсутствующее значение не равно нулю. Ноль показывается только при наличии подтверждённого нулевого значения.
- Частичный каталог не означает, что у агента нет детей. Неполнота или недоступность источника должны быть обозначены.
- Состояние выполнения, результат задачи и свежесть данных — три разных понятия; одно нельзя выводить из другого.
- `idle` означает только подтверждённое состояние покоя агента. Оно не означает успешное завершение задачи.
- `disposed`, отсутствие объекта или потеря связи не являются результатом задачи.
- Не выводить внутренние мысли, скрытые фазы, ожидаемое намерение модели или успешность из косвенных признаков.
- Моковые и демонстрационные данные не выдаются за данные живого Desktop.

### 3.4. Минимизация данных

- Панель раскрывает только сведения, необходимые для обзора текущего состояния.
- Полные промпты, содержимое сессий, полные логи, секреты, учётные данные и заголовки запросов не показываются и не сохраняются.
- Короткий заголовок сессии разрешён на карточке по прямому решению пользователя. Он может быть производным от первых слов пользовательского сообщения; панель показывает только уже принятую проекцию заголовка и не читает и не хранит текст исходного сообщения или полный лог ради этого.
- Техническая диагностика ограничена ключевыми переходами и категориями ошибок. Она не содержит ID агентов/сессий, названий, моделей, текста ошибок или содержимого сессий; обнаруженные ошибки источника также кратко показываются в подробностях агента.
- Краткая задача показывается только при наличии подтверждённого безопасного источника. Пока такого источника нет, текст — **«Задача недоступна»**.
- Данные панели хранятся только в памяти процесса плагина; продукт не строит постоянную историю.

## 4. Термины и значения в интерфейсе

| Термин | Продуктовое значение |
|---|---|
| **Host** | Один работающий backend официального DeepSeek Harness Desktop, за которым наблюдает панель. |
| **Живой агент** | Агент, присутствующий в актуальном реестре агентов Host. |
| **Известный подагент** | Дочерняя сессия, обнаруженная в каталоге. Это не утверждение о её текущей активности. |
| **Running** | Источник явно сообщает, что живой агент выполняется. |
| **Idle** | Источник явно сообщает, что живой агент сейчас не выполняется. Это не outcome. |
| **Unknown / Unavailable** | Надёжного значения нет. Не трактовать как ноль, отсутствие или ошибку задачи. |
| **Partial** | Некоторые источники или ветви наблюдения недоступны, поэтому состав панели может быть неполным. |
| **Connected** | Браузер получил начальное состояние и/или поддерживает живой канал. Это не обещание полной видимости всех данных. |
| **Stale / Reconnecting / Disconnected** | Состояние свежести или канала связи; оно не является состоянием агента. |
| **Estimated** | Метрика выведена или приблизительна, а не получена как точное подтверждённое значение. |

Если версия Harness предоставляет другие собственные статусы, плагин не переименовывает их в один из этих терминов без документированного соответствия.

## 5. Данные и их трактовка

### 5.1. Агент

Карточка может показывать заголовок сессии, идентификатор, тип/родителя, подтверждённое состояние, последнюю подтверждённую активную модель и доступные метрики. Модель обновляется по каждому подтверждённому заголовку запроса, включая заголовок, пришедший непосредственно перед переходом в `Running`; пока нового заголовка нет, отображается последнее подтверждённое значение. Если проекция заголовка недоступна, карточка показывает короткий ID; полный ID остаётся доступен отдельно.

Сохранённая сессия может отображаться до того, как Desktop загрузит для неё живого агента. В этом случае текущий статус остаётся `unknown`; заголовок, последняя подтверждённая модель и доступные сохранённые метрики читаются через официальный API проекций. Отсутствующие сведения остаются недоступными. Панель не возобновляет и не открывает такую сессию ради наблюдения.

### 5.2. Токены и контекст

- Показывать только реально доступные счётчики: input, output, cache read и cache write.
- Сводка `Tokens available` — сумма известных числовых счётчиков в текущем снимке. Рядом обозначается, сколько счётчиков вошло в сумму; эта сумма не является стоимостью запроса или размером контекста.
- Неизвестные составляющие остаются `Unavailable`; их нельзя подставлять как ноль в отдельные показатели.
- Контекст показывать как `used / capacity` только если доступны оба значения. Оценочное значение явно помечать `estimated`.
- Контекст и счётчики токенов могут обновляться с разной полнотой и в разное время.

### 5.3. Подагенты

- Дерево отражает только подтверждённые связи родитель → ребёнок.
- Счётчик известных подагентов означает число дочерних записей в текущем снимке, а не число выполняющихся дочерних агентов.
- Состояние дочернего узла `running` допускается только при наличии подтверждённого живого состояния.
- Недоступный родитель, каталог или потомок не заменяются предполагаемым пустым деревом.

## 6. Продуктовый объём MVP

### 6.1. Обязательное пользовательское поведение

- Браузерная обзорная панель с реальными данными одного Host.
- Сводные числа и адаптивные карточки агентов.
- Поиск по доступным идентификаторам/именам/моделям; фильтры по статусу и типу.
- Иерархический вид обнаруженных агентов и подагентов.
- Просмотр подробностей выбранного агента.
- Доступные метрики контекста и токенов с честным обозначением неизвестного и оценочного.
- Автоматическое обновление без ручного обновления страницы.
- Сортировка ставит все `Running` карточки перед карточками с любым другим статусом; порядок среди работающих определяется последним переходом в `Running`.
- Видимые состояния подключения, свежести и неполноты.
- Интерфейс читаем при разных размерах окна; число колонок определяется доступной шириной, не фиксированным максимумом.
- Утверждённое тёмное визуальное направление, подписи для метрик и семантики, не зависящие только от цвета.

### 6.2. Ограничения доступа как требование продукта

- Поддерживается только локальный loopback-доступ; LAN и публичная публикация не входят в MVP.
- Начальное сопряжение выполняется явно из Desktop и ограничивает доступ этой панелью.
- Сопряжение одноразовое и краткосрочное; сессия браузера привязана к authority текущего Host. При смене порта требуется новое сопряжение.
- Все каналы чтения и обновления должны требовать авторизацию и проверять ожидаемое происхождение запроса.
- Loopback сам по себе не считается авторизацией.

Конкретные механизмы, сроки, cookie, API и границы версий определяются и доказываются в `docs/COMPATIBILITY.md`; они не считаются возможностями Harness только потому, что указаны в проектном дизайне.

### 6.3. Вне MVP

- Управление агентами, команды и изменение задач.
- Запуск/возобновление сессий из панели.
- Несколько Hosts и агрегирование разных экземпляров.
- Общедоступная интернет-панель или LAN-режим.
- Полные промпты, сессионные логи и приватное содержимое.
- История, Timeline, графики прошлых запусков, уведомления.
- Отдельный процесс Harness или отдельный сервис, который дублирует Desktop.
- Неподтверждённые сведения о ходе мысли, результате или будущей активности.

## 7. Принципы интерфейса

- Главная поверхность — обзор карточек; отдельные виды — дерево и панель подробностей.
- Статус агента, свежесть канала и полнота источников показываются раздельно.
- Цвет статуса дополняется текстовой подписью или другим доступным обозначением.
- Тёмная палитра использует глубокие синие поверхности, тонкие границы, светлый основной текст и синий акцент. Цветовые категории метрик имеют разные оттенки и подписи.
- Основной шрифт — доступный локальный моноширинный шрифт с поддержкой кириллицы. Classic Console Neue используется только после проверки конкретного файла, глифов и лицензии; иначе применяется системный monospace fallback.
- На узких экранах карточки перестраиваются без горизонтального переполнения; на широких число колонок растёт по доступной ширине.

## 8. Критерии продуктовой приёмки

MVP соответствует продуктовым требованиям, когда все пункты ниже подтверждены на заявленной целевой версии Desktop:

1. Панель связывается с одним работающим экземпляром Desktop и отображает настоящий снимок без моковых данных.
2. Для агента различимы `running`, `idle` и недоступное состояние; idle не представляется как успешный outcome.
3. Изменение агента видно в открытом браузере автоматически, без ручного reload.
4. При потере потока интерфейс показывает stale/reconnecting/disconnected, а после восстановления получает согласованный свежий снимок.
5. Подагенты отображаются только при подтверждённой связи; наличие записи в каталоге не означает running.
6. Неизвестные метрики остаются недоступными, оценки маркируются, неполнота видна.
7. Детали задачи не раскрывают текст, пока не подтверждён безопасный источник.
8. Незапароленный, неподходящий по authority или cross-origin доступ не раскрывает snapshot или поток событий.
9. Дашборд не запускает, не меняет и не останавливает задачи.
10. Интерфейс остаётся читаем при разных размерах окна, а число колонок не ограничено произвольным максимумом.

Целевой срок отражения изменения — до 2 секунд после того, как событие стало доступно сборщику. Это продуктовая цель при исправной локальной связи, а не гарантия, что Harness или провайдер сообщит каждое внутреннее изменение за это время.

## 9. Текущее свидетельство и ограничения

На 2026-10-14 на одной установке Desktop `0.2.0-rc.2` пользователь подтвердил успешное сопряжение, получение снимка, открытый SSE и отображение live-обновления активной сессии. Начальный снимок содержал одного root-агента `idle`, ноль известных подагентов, доступные счётчики токенов и статус полноты `Partial`. 2026-10-15 пользователь отдельно разрешил показывать принятый заголовок сессии в панели, включая его изменение; исходный текст сообщения и лог по-прежнему не раскрываются.

Это подтверждает пользовательский сценарий на данной установке, но не расширяет поддержку на другие версии и не доказывает все критерии приёмки. Переподключение после обрыва, resync, живой сценарий с подагентом и полнота доступных метрик остаются отдельными проверками. Подробные технические свидетельства и границы уверенности находятся в [`COMPATIBILITY.md`](COMPATIBILITY.md).

## 10. Изменение спецификации

Предложение, меняющее бизнес-правило или MVP, описывается как явное изменение этой спецификации: причина, изменяемое правило, влияние на приватность/безопасность, пользовательский эффект и критерий приёмки. До принятия такого изменения реализация следует текущей версии документа.


### Уточнение холодного отображения (2026-10-18)

Заголовок, последняя подтверждённая модель и доступные сохранённые метрики должны заполняться при первом открытии панели без выбора сессий в Desktop. Для этого разрешено чтение проекций через официальный read-only API; панель получает только выбранные метаданные. У незагруженной сессии текущий runtime status остаётся неизвестным, а метрики относятся к сохранённому состоянию. Чтение не запускает и не возобновляет агента.
